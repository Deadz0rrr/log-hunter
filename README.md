# log-hunter

Консольный инструмент на Python для поиска атак в серверных логах. Читает `auth.log` (SSH) и `access.log` (nginx), находит брутфорс, успешный вход после подбора пароля и сканирование путей, и выдаёт короткий отчёт с уровнями критичности, как первичная сортировка алертов в SOC.

## Что умеет

| Находка | Лог | Критичность |
|---|---|---|
| Успешный вход после серии неудачных попыток (пароль, вероятно, подобран) | auth.log (SSH) | HIGH |
| Брутфорс: N неудачных входов за T минут с одного IP | auth.log (SSH) | MEDIUM |
| Сканирование путей: много 404 на разные URL (ffuf, gobuster, боты) | nginx access.log | LOW |

## Запуск

Нужен Python 3.10+. Сторонних библиотек нет, только стандартная (`re`, `datetime`, `argparse`); `pytest` нужен только для тестов.

```
python -m log_hunter --auth samples/auth.log --nginx samples/access.log
```

Флаги:

| Флаг | Что делает | По умолчанию |
|---|---|---|
| `--auth` | путь к auth.log | — |
| `--nginx` | путь к nginx access.log | — |
| `--threshold` | сколько неудач считать брутфорсом | 5 |
| `--window` | окно для брутфорса, в минутах | 10 |

Можно передать только один лог, например `--nginx samples/access.log`.

## Пример вывода

```
[HIGH  ] 198.51.100.23   вход после 3 неудач (user: admin)
[MEDIUM] 203.0.113.66    брутфорс SSH
[LOW   ] 203.0.113.9     сканирование путей
Найдено угроз: 3
```

В `samples/` лежат синтетические логи с тремя атаками и двумя «обычными» пользователями (человек, который раз в час ошибается в пароле, и посетитель сайта с опечаткой в URL). Детекторы ловят атаки и не поднимают ложных тревог на обычных пользователей.

## Как это работает

1. **Парсеры** (`log_hunter/parsers.py`) разбирают каждую строку лога регулярным выражением с именованными группами и превращают её в словарь: `{'ip', 'user', 'event', 'ts'}` для SSH и `{'ip', 'path', 'status', ...}` для nginx. Строки, которые не относятся к делу (cron и т.п.), отбрасываются.
2. **Детекторы** (`log_hunter/detectors.py`) группируют события по IP и проверяют условие:
   - *брутфорс* — для каждого IP сортируются времена неудач, и **скользящее окно** проверяет, уместились ли N неудач подряд в T минут;
   - *вход после неудач* — события идут по порядку, для каждого IP считается серия неудач, при успешном входе серия проверяется и обнуляется;
   - *сканирование* — для каждого IP считаются ответы 404 и множество (`set`) уникальных путей.
3. **CLI** (`log_hunter/__main__.py`) разбирает флаги через `argparse`, запускает нужные детекторы и печатает отчёт, сверху самое критичное.

```
log_hunter/
  __main__.py    # CLI и отчёт
  parsers.py     # auth.log и nginx access.log
  detectors.py   # брутфорс, вход после неудач, сканирование
tests/           # pytest
samples/         # синтетические логи (без реальных IP и имён)
```

## Тесты

```
python -m pip install pytest
python -m pytest
```

Тесты проверяют парсер (правильная строка, мусорная строка) и детекторы с двух сторон: атака найдена и обычный пользователь не помечен.

## Ограничения и планы

- В auth.log нет года, поэтому год подставляется фиксированный. Лог на стыке 31 декабря и 1 января разберётся неверно.
- Порог для «входа после неудач» пока задан в коде (3), стоит вынести в отдельный флаг.
- Хочу добавить вывод в JSON (`--format json`) для отправки в SIEM.
- Хочу добавить правило: если сканер получил ответ 200 на чувствительный путь (`/.env`, `/.git/config`), повышать критичность до HIGH.
- Поддержка других форматов: Windows Event Log, journald.
